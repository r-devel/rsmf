   - Reported upstream to R Core. Each fix was filed on R's Bugzilla with a patch and a regression test, and several have already landed in R trunk (sprintf huge widths, the strsplit overflow, the weak-reference finalizer PROTECT bug, the parser stale-id timeout).
       + Use priority on Bugzilla reports to help R Core judge priority of these patches
   - Kept the fuzzer build patched in the meantime. The r-oss-fuzz repository carries each fix as a patch until it lands upstream, with CI that flags patches that drift or become redundant.
   - Also added new fuzz targets and instrumented libdeflate.
   - There was a spurt of bugs when first added to OSS-Fuzz and another spurt when another couple of fuzzers were activated. Expect to slow down to about a couple of bugs a month.
   - Discussion about how it works;
     + We define the fuzz harnesses, ask OSS-Fuzz to run them and allocate 2 hours to this. Not sure if we have control over how much time we spend on each fuzzer, Kevin will need to look into that.
     + So more harnesses implies less time on each one. Kevin will see if it's possible to alternate between sets.
     + Everything is private by default, but there is a 90-day disclosure which makes bugs public on OSS-Fuzz once a fix has been patched into the build that is being fuzzed (not necessarily upstream to R-devel)
   - Plans to catch up with Simon after his semester finishes in the coming weeks.
